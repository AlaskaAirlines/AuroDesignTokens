# AB#1619704

## Executive Summary

The design tokens project carried an outdated, half-renamed theme and an unnecessary external dependency. One theme was called "auro-1" in the build but "atmos" everywhere else (documentation, web/app outputs), and an obsolete "auro-2" theme was still being generated. The build also pulled all of its core token data from an external package (`auro-tokendefinitions`), an outdated process.

This work removed the obsolete "auro-2" outputs, brought the token source in-house so the project no longer depends on the external package, and finished renaming "auro-1" to "atmos" consistently across the entire build and its generated files. The result is a cleaner, self-contained, predictable token build with a single consistent name for the Atmos theme. Ticket: [AB#1619704](https://itsals.visualstudio.com/E_Retain_Content/_workitems/edit/1619704).

## The Problem

The tokens project was confusing to work in and easy to make mistakes with for three reasons:

- It still produced a stale "auro-2" set of theme files that nobody needed.
- A single theme had two names — the build called it "auro-1" while the docs and the rest of the project already called it "atmos."
- Every core token value was fetched from an external package at build time, an outdated dependency that made the build harder to reason about and maintain.

Carrying obsolete files and mixed naming risked shipping the wrong tokens and slowed down anyone working in the project.

## Root Cause

The modern themes pipeline sourced its tokens from the external `@aurodesignsystem/auro-tokendefinitions` package via `PATHS.TOKENS_DEFS` in `src/config/constants.js`. The theme's `dir` field in `src/config/themes.js` did double duty: it was both the **source lookup path** inside that package (e.g. `.../semantics/web/auro-1/`) and the **output directory name** (`dist/themes/auro-1/`). Because the upstream package only shipped an `auro-1` directory, the output name was effectively locked to the upstream naming — it could not be renamed to `atmos` without either the upstream package changing or decoupling source from output.

Separately, `THEME_DEFINITIONS` still contained an `auro-2` entry, so the build kept generating `dist/themes/auro-2/*`, and an obsolete `dist/tokens.zip` lingered. Meanwhile the rest of the project had already standardized on the Atmos name and the `atm` code (`README.md` theme table, `WEB_THEME_DEFINITIONS` in `constants.js` using `aag-theme-atm`), so the `auro-1` / `a1` naming in the build was the lone inconsistency.

## The Fix

The work landed in three commits on `jbaker/oldAtmosCleanup`:

1. **Remove auro-2** (`7f24ff1`): dropped the `auro-2` entry from `THEME_DEFINITIONS`, deleted the generated `dist/themes/auro-2/*` output, removed the stale `dist/tokens.zip`, and regenerated the bundled CSS without the auro-2 layer.

2. **Remove the external dependency** (`fb4be09`): vendored the 123 consumed token files into `tokenDefinitions/coreTokens/` (mirroring the package's `primitives/` and `semantics/web/` layout), repointed `PATHS.TOKENS_DEFS` to `./tokenDefinitions/coreTokens`, updated the stale wording in `test/tokenConsistency.js`, and removed `@aurodesignsystem/auro-tokendefinitions` from `package.json` and `package-lock.json`.

3. **Rename auro-1 → atmos** (`8cfb949`): now that the source directories are owned locally, renamed `coreTokens/primitives/auro-1` and `coreTokens/semantics/web/auro-1` to `atmos`; changed the `THEME_DEFINITIONS` entry to `{ dir: 'atmos', name: 'Atmos', code: 'atm' }`; regenerated output as `dist/themes/atmos/*` (removing `dist/themes/auro-1/*`), which also changed the primitive variable prefix from `$a1-*` to `$atm-*` and the bundled CSS selector from `aag-theme-a1` to `aag-theme-atm`; refreshed the naming-example comment in `scripts/styleDictionary.mjs`; and updated `docs/migration.md`.

## Why This Works

Vendoring the token source removed the coupling that blocked the rename: the local `coreTokens/` directories are ours to name, so `auro-1` could become `atmos` directly without decoupling the `dir` field or waiting on the upstream package. The rename was applied at every layer — source dirs, the theme definition (`dir`/`name`/`code`), generated `dist` output, variable prefixes, CSS selectors, and docs — so no half-renamed state remains.

Correctness was verified structurally, not just by inspection: `npm run build` regenerates cleanly and the token-consistency tests pass. Token **values** are unchanged by the dependency removal — the only `dist` difference from vendoring is the embedded source `filePath` metadata now pointing at `tokenDefinitions/coreTokens`. The `atm` code was chosen (over keeping `a1`) specifically because `README.md` and `WEB_THEME_DEFINITIONS` already documented Atmos as `aag-theme-atm`, so the change resolves the inconsistency rather than introducing a new one. A repository-wide search confirmed no non-historical `auro-1` / `auro-2` references remain; CHANGELOG and post-mortem mentions were intentionally left intact.

## Outcome

- The obsolete Atmos-2 ("auro-2") files are gone and are no longer produced by the build.
- The tokens build is now self-contained — it no longer depends on the external token package and builds entirely from data inside the repository.
- The Atmos theme has a single, consistent name across the build, its generated files, and the documentation.
- The full build and the token-consistency checks pass, confirming nothing broke and token values are unchanged.

## Learnings

- When a single identifier is used as both an external source path and a local output name, the two are coupled — you can't rename the output without either changing the upstream source or decoupling the fields. Owning the source (vendoring) is often the cleanest way to break that coupling.
- Sequencing mattered: removing the external dependency first made the rename a trivial local directory move, avoiding a more invasive `sourceDir`-vs-output decoupling in the build config.
- Choose the surviving name by what the rest of the project already uses. `README.md` and `WEB_THEME_DEFINITIONS` had already standardized on `atm`/Atmos, which made `code: 'atm'` the correct choice and turned the rename into a consistency fix.
- Generated `dist` files embed source `filePath` metadata, so a pure source-location change still shows up as a `dist` diff — confirm token **values** are unchanged rather than assuming an empty diff.

## Iterations That Didn't Work

- **Decoupling `sourceDir` from the output `dir` in the build config.** The initial plan for the rename (before the dependency-removal requirement was added) was to add a separate `sourceDir` field to `THEME_DEFINITIONS` so `dir: 'atmos'` could point at the upstream `auro-1` source directory. This was necessary only because the source lived in the external package. Once the tokens were vendored locally, the source directory could simply be renamed to `atmos`, so the decoupling was abandoned as unnecessary complexity.
